# Versioned offline shell (#23)

The service worker precaches only a fixed list: app HTML, public backend configuration, existing crypto/date/appearance code, manifest/icons, self-hosted font and gong. It never handles cross-origin, non-GET, query-bearing, auth/API or arbitrary resource requests. Cache requests use static URL keys, without request credentials/headers. The app checks HTML identity/version during install so a protection/login/error page cannot become its shell. Precache consumes font/audio response streams immediately to avoid stalled queued requests.

Shell/assets stay together in one explicit version cache. The Vercel build injects the app's `APP_VERSION` into its worker; for source/local review both constants must match. Every application/asset release must bump `APP_VERSION`. New workers wait while app windows remain open, show a quiet update notice and activate when all app windows close. No forced reload, skipWaiting, user-storage deletion or background sync. Activation cleans only obsolete `clean-time-shell-v1-` caches. Online events retain the existing registered sync retry and also check for a shell update.

The optional connectivity copy follows the browser's `navigator.onLine` heuristic; actual connectivity and successful cloud sync remain independent. A cached app can open/use/save local recovery tools when requests are unavailable. A first-ever offline visit cannot install the shell. External readings/initial account login require a connection; the remote SDK and Auth responses are not cached. Previously available local registered data remains usable; the existing backup state/key rules still apply.

Focused synthetic Chromium: offline shell/lifecycle **16** + backend/build isolation **25** = **41 checks**, no failures. A worker-level cache-storage fault is observed and verifies safe online network fallback without recovery loss. Real browser network-offline mode covers reopen, planner, gratitude, journal, inventory, bookmarks, legacy data, local font/icon/audio fetches and no auth/query fallback. A bounded local synthetic HTTP origin verifies old-window stability, update notice, all-windows-closed activation, new-version reopen, recovery preservation and cache cleanup that retains an unrelated cache. Registered reconnect uses the existing encrypted SDK fixture under actual browser offline mode, asserting no upload until reconnect and one complete encrypted pending upload afterward.

Full regression and protected exact-head Preview totals appear in the PR. These are browser/synthetic checks, not live Auth/PostgREST, physical Android/PWA, real email or subjective product acceptance. Offline installation/update failures remain fail-safe; current local recovery data is not cleared. No production data/configuration, SQL, crypto changes, merge or production deployment.

Strategy reference: [MDN service-worker lifecycle](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers). Refs #23/#37; separate from portable export because caching/update/Auth boundaries need independent review.
